# Audit antislop 001 - RDI Indirect Scanner (rdi-scanner-pwa)

- Tanggal: 2026-11-01
- Target: `C:\projec\rdi-scanner-pwa` (index.html 665 KB, Code.gs 257 KB, 563 berkas non-.git)
- Mode antislop: `during` (global preference, `%APPDATA%\antislop\settings.json`)
- Metode: audit statis (HTML/CSS/JS dibaca langsung). Aplikasi tidak dijalankan karena butuh backend Google Apps Script aktif.
- Batas: tidak ada render/klik nyata, jadi temuan R-35 dan perilaku runtime belum terbukti. Tidak ada kode yang diubah.

## Ringkasan

| Prioritas | Jumlah |
|---|---|
| HIGH (Hard Gate) | 8 |
| MEDIUM (Purpose-Gate) | 2 |
| LOW (Quality Lock) | 2 |

Kesan umum: ini aplikasi yang sudah mature dan sudah pernah dibersihkan aksesibilitasnya (token kontras, focus-visible, aria-live, skip link, pengurangan target sentuh). Slop khas "AI landing page" tidak ada karena ini tool internal, bukan halaman marketing. Temuan di bawah ini sobekan kecil, bukan pembongkaran.

## Temuan

### 1. R-02 - 87 em dash di teks yang tampil (HIGH, perlu keputusan pemilik)

Bukti: `index.html` - judul tampil "RDI Indirect Scanner - Manajemen Inventaris Spare Part, Tools & Indirect"; 87 karakter `-` di teks yang dirender, 198 baris ber-em dash bila komentar ikut dihitung.

Alasan: R-02 melarang em dash pada teks yang ditulis agen. Teks ini tulisan pemilik produk, dan aturan mewajibkan protokol konflik: sebut karakternya, sebut aturannya, tanya. Jadi bukan pelanggaran otomatis, tetapi butuh keputusan: pertahankan (gaya penulis) atau ganti dengan `,` / `:` / `()`.

### 2. R-37 - Tidak ada DESIGN.md / arah desain tertulis (HIGH)

Bukti: tidak ada `DESIGN.md` di repo; arah desain hanya tersirat di komentar CSS (mis. "REVISI DESKTOP v14.94", "UX-05: 4.17:1 -> 6.9:1") dan token `:root` di `index.html` (baris 43-50).

Alasan: token desainnya bagus dan konsisten (`--brand-1 #0057C2`, `--brand-2 #0060DF`, `--bg #F1F4F9`, `--text #0F172A`, skala radius `--br-2..--br-999`, elevasi `--elev-1..3`), tetapi tidak ada dokumen yang menyatakan identitas, palet, tipografi, dan alasan pemilihannya. Tanpa itu, setiap perubahan berikutnya rawan jatuh ke default AI.

Saran: buat `DESIGN.md` yang mendokumentasikan apa yang **sudah** dipakai (bukan mengganti arah): brand navy-blue, palet netral `--neutral-*`, semantic green/red/amber, Inter + JetBrains Mono, skala radius dan elevasi.

### 3. R-39 - Pola tab ARIA tidak lengkap (HIGH)

Bukti: 11 `role="tab"` (mis. baris 870, 874, 878; tablist di 869, 1587, 2021), tetapi `role="tabpanel"` = 0 dan `aria-controls` = 1 (baris 1433, bukan pada tab).

Alasan: pola tab ARIA yang setengah jadi membingungkan screen reader: tab mengumumkan dirinya sebagai tab, tetapi panel yang dikendalikan tidak pernah diumumkan. Pilih salah satu: lengkapi (`aria-controls` per tab + `role="tabpanel"` + `aria-labelledby`), atau turunkan menjadi tombol navigasi biasa dengan `aria-current="page"`.

### 4. R-39 - Landmark hanya `nav` dan `main` (HIGH)

Bukti: `<nav class="tabnav" role="tablist">` baris 869, `<main id="main-content" tabindex="-1">` baris 898. Tidak ada `<header>` maupun `<footer>`.

Alasan: aturan mewajibkan landmark `header`, `nav`, `main`, `footer` untuk satu dokumen utuh. `.topbar` yang sudah ada bisa dinaikkan menjadi `<header>`, dan baris status/catatan kaki menjadi `<footer>`.

### 5. R-03 - Beberapa target sentuh di bawah 44px (HIGH)

Bukti (blok CSS minified, `index.html` baris 50-247): `.btn-sm { min-height:40px }`, `.btn-sm { min-height:34px }`, `.th-sortable>button { min-height:24px }`, `.hist-card-detail-btn { min-height:24px }`. Ada juga override ke 44px dan 48px di aturan lain.

Alasan: 34px dan 24px di bawah minimum 44px. Perlu dipastikan aturan mana yang menang di viewport HP: kalau yang menang versi kecil, ini pelanggaran Hard Gate. Saran: jadikan 44px sebagai default `.btn-sm` dan longgarkan hanya di media query pointer halus (`@media (pointer:fine)`).

### 6. R-32 - Satu input hanya menandai fokus lewat warna border (HIGH)

Bukti: `.hist-search-input:focus { outline:none; border-color:var(--amber) }` (blok CSS, `index.html` baris 54).

Alasan: indikator fokus wajib jelas dan tidak boleh hanya mengandalkan warna. Input lain sudah benar (`input:focus` memakai ring `box-shadow: 0 0 0 3px rgba(10,132,255,.15)`). Saran: samakan dengan ring, atau tambahkan `:focus-visible { outline:2px solid var(--amber); outline-offset:2px }`.

### 7. R-40 - `<img>` tanpa dimensi (HIGH)

Bukti: `index.html` baris 1255: `<img id="sj-preview" class="preview" alt="Pratinjau SJ" style="margin-top:8px">`.

Alasan: gambar pratinjau (data URI yang diisi JS) tidak punya `width`/`height`/`aspect-ratio`, sehingga layout bergeser saat foto surat jalan dimuat. Saran: tetapkan `width`/`height` atau `aspect-ratio` di CSS `.preview`.

### 8. R-26 - Satu tautan aksi ber-`href="#"` (HIGH)

Bukti: `index.html` baris 2394: `<a href="#" onclick="openAsetTambahItemModal(true);return false">+ Daftarkan`.

Alasan: perilakunya nyata (membuka modal), tetapi `href="#"` adalah tujuan hantu; tanpa JS tautan melompat ke atas halaman. Saran: ganti menjadi `<button type="button">` bergaya tautan.

### 9. R-10 - Glassmorphism di 5 elemen (MEDIUM)

Bukti: `backdrop-filter` pada `.id-search-loading` (baris 51), `.item-detail-overlay`, `.modal-overlay`, `.tabnav`, `.bottom-sheet-overlay`.

Alasan: batas dosis aturan adalah 1-2 elemen. Overlay memang wajar memakai blur (transien, menandakan lapisan), tetapi `.tabnav` adalah elemen permanen, jadi totalnya melewati dosis. Saran: tulis alasan pemakaian di komentar, atau lepas blur dari `.tabnav`, sisakan overlay + loading.

### 10. R-06 - Inter + JetBrains Mono tanpa alasan tertulis (MEDIUM)

Bukti: `--font-sans: 'Inter',...` dan `--font-mono: 'JetBrains Mono',...` (blok CSS baris 43-50).

Alasan: keduanya termasuk pilihan default AI. Boleh dipakai, tetapi butuh alasan tertulis (keterbacaan angka di tabel, konsistensi dengan dokumen internal) atau diganti dengan typeface yang lebih khas RDI. JetBrains Mono untuk sel angka memang masuk akal; Inter untuk UI perlu dibuktikan, bukan diasumsikan.

### 11. R-34 / R-31 - CSS tema gelap sisa (LOW)

Bukti: tema gelap sengaja dihapus. Komentar `index.html` baris 2893-2898: tombol ganti tema dibuang karena "topbar di HP sudah padat", lalu `document.body.classList.add('light')` dan `localStorage.removeItem('rdi_theme')`. Namun di CSS masih ada 35 aturan `body.light ...` dan 1 aturan `body:not(.light) ...`.

Alasan: aturan `body:not(.light)` adalah sisa tema yang tak pernah aktif, jadi kode mati dan sumber kebingungan. Saran: hapus percabangan `body.light` (karena semua tampilan sekarang terang), atau kembalikan toggle bila operator butuh gelap.

### 12. R-40 - Library berat dimuat di awal (LOW)

Bukti: `js/xlsx.full.min.js` 861 KB dan `js/exceljs.min.js` 925 KB dimuat dengan `defer` sejak awal; jsPDF 356 KB dan html2pdf 885 KB sudah benar karena diinjeksi saat dibutuhkan (komentar baris 3859: "unduh ulang 1,27 MB tiap klik" sudah sadar masalah ini).

Alasan: ±1,8 MB untuk fitur impor/ekspor yang belum tentu dipakai tiap sesi. Bukan pelanggaran keras, tetapi paling berdampak pada HP lapangan. Saran: muat `xlsx`/`exceljs` saat tombol impor/ekspor ditekan, seperti pola jsPDF yang sudah ada.
